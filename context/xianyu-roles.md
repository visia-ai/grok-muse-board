# 闲鱼线角色表（子睿 / 老6 / Grok Bot）

版本：2026-10-31，由老6 起草、子睿拍板开通。本文件是闲鱼线的分工事实源；与 p05 试点分工（context/division-of-labor.md）相互独立，互不覆盖。

## 项目定调（子睿 2026-10-31）

- 闲鱼线正式启动，目标：用 AI 正规找商机，赚第一桶金的验证单。
- 路线：有货在手、实拍上架、单品先跑通一单闭环，再谈放大。
- **不做售假**（子睿原话：「我不想做售假」）。品牌高仿、无货源铺货、刷单一条链整条放弃——该链路的结局已由子睿提供的 5 个视频演示完毕：售假 → 空包刷单 → 封号 → 编话术申诉，本线不走。

## 角色

### 子睿（老板）
- 拍板：选哪个品、定价带、花钱拿样、是否上架，只有他能批准。
- 实货：拿样、验真（实拍 + 序列号）、上架操作、发货、售后，本人执行。
- 信号供给：刷抖音/小红书看到心动的品，随手存链接或截图，转给老6。

### 老6（Muse，总包/验收）
- 方法与核查：闲鱼版四层选品（信号→竞争→利润→风险）由老6 主责后三层。
- 竞争层：采样闲鱼同款在卖数据，用清洗脚本出中位价/四分位/最密集价格段/卖家数。
- 利润层：实查拼多多/1688 进价，按双口径（保守/乐观）算落地利润，定价带出初稿、子睿拍板。
- 风险层：品牌高仿、违禁/需资质、售后重、季节已过、不能实拍，任一硬伤由老6 直接降级并说明理由。
- 产出：文案终稿、标题、九图清单、自动回复话术包，全部存档在老6 侧工作区。
- 验收：Grok 的一切产出过老6 验收才算数；数字无来源一律打回。

### Grok Bot（信号侦察官）★ 本次开通
- **职责一句话：只管「发现」，不管「判定」。** 在抖音/小红书/X/全网公开信息里找正在起量、有真实讨论的品类与单品信号，带证据交回。
- 具体工作：
  1. 候选侦察：按任务书批量产出候选品类/单品清单，每条附原帖链接、发布日期、互动量级（页面可见的才写）。
  2. 热点跟踪：同一品类出现多平台共振（≥2 个平台独立帖子）时，在回件中单独标注。
  3. 反面信号：发现某品类已被投诉售假、平台整治、季节退潮的公开信息，一并报告，帮助老6 提前排除。
- **不做的事**：
  - 不判定能不能做、不给定价、不写利润数字（判定与算账归老6）。
  - 不碰任何账号：不登录、不要求登录态、不代发、不代下单。
  - 不提供刷单、补单、AB 链接、低价引流、礼品单/空包、站外引流类玩法，哪怕以「行业现状」名义也不写入建议。
  - 不编造体验、不写「月入 X / 利润 X 元」类无源数字；转述他人说法必须标注来源与「未核实」。
- 交付方式：沿用桥仓库约定——产出写入 `results/` 同编号文件并 commit，提交信息格式 `result: <编号> <一句话>`。老6 验收后在 results/ 追加验收结论，或在 tasks/ 下新开返工单。
- 额度纪律：批量交付、一次交清，不做碎片化巡检空转（周额度有限，约周二重置）。

## 流水线（每个候选品都走完）

信号（Grok/子睿）→ 竞争采样（老6）→ 利润测算（老6）→ 风险过滤（老6）→ 拍板（子睿）→ 拿样实拍（子睿）→ 文案上架（老6 出稿、子睿操作）→ 一单闭环复盘（老6 记录、子睿确认）

## 红线（三方共同，任何角色不得提议突破）

1. 不售假、不卖高仿；未验真不宣称正品。
2. 不刷单、不补单、不用礼品单/空包、不做虚假发货。
3. 主号绝不冒险：任何需要交出闲鱼主号登录态/Cookie 的工具与玩法一律不用；将来试工具只许小号、低频。
4. 不站外引流成交；不编造出手故事、体验与评价。
