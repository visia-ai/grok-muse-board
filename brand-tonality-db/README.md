# 品牌调性数据库

这不是插件清单，也不是品味条文汇编。

它的最终目的，是抽象出一套以后接单时能高效率调用的 SOP：面对一个具体品牌，快速判断「什么场景、用什么象征、配什么元素、走什么流程」，再才落到插件去实现。

插件库并入本目录，但只作为中间层。插件是实现手段之一，不是主体。主体是设计决策：场景 + 象征 + 品牌元素 + 插件功能，四位一体地想清楚「这一次怎么做成一个创新的设计」。

## 给谁用、怎么长出判断

给子睿接单时调用，也给一起做展示站的 agent（包括品牌调性调研师）读。

读法不是先背「高级必须怎样、廉价禁止怎样」，再拿清单去套客户。那是机械执行。这里用的是侧面学习：通过大量成对的案例反复接触——同一场合不同象征，同一种象征的高级做法和廉价做法——慢慢形成接近人的判断。维度表是读完案例之后，用来互相说话的词汇，不是入学第一课的戒律。

新收录一个插件或一个网站时，不要只加一行名字。请写成一条四位一体的案例：它适合什么场合、表达什么象征、动用哪些品牌元素、哪些插件功能可以怎样组合。案例多了，SOP 才会越来越好用。

## 四位一体

每一条案例都按同一框架写，也按同一框架被调用：

| 位 | 问的是 | 例如 |
|---|---|---|
| 场景 | 这是什么场合、客人带着什么心情来 | 婚礼、产品发布、个人品牌、线下空间、山居、咖啡馆、花艺、摄影档期、理疗 |
| 象征 | 这一次要让人感到什么意义 | 仪式感、克制、力量感、在地、疗愈、文学、透明、五感 |
| 品牌元素 | 这个品牌自己已经有、可以拿来做设计的东西 | 产地、材料、人物、建筑旧身、工序、季节、气味、一句话 |
| 插件功能 | 用什么技术能力把元素做成可感知的体验 | 揭幕、转场、横滑、图墙、对比滑块、字体切片、模糊占位、预约嵌入 |

创新发生在组合里：不是「用了 GSAP 所以高级」，而是「把瓦厂曾经是琉璃瓦厂这件事，用杂志揭幕加顺滑滚动讲出来」。

## 维护

- 不存放账号、密码、token 或客户未公开材料。
- 不编造流量、奖项或客户没有的故事。
- 许可风险以插件索引里的风险栏为准。
- 标签不随每一条新收录改名；只有出现新的可感知气质时才新增案例类型。
